# Internationalization

Tripto supports English (`en`), German (`de`), French (`fr`), Spanish (`es`) and Russian
(`ru`). English is the resilient default and the fallback: no screen ever shows a raw key,
an empty string, or `undefined`. On first visit the app detects the browser locale
(`navigator.language`, normalized to a supported base language); after that the saved
preference wins. A guest preference lives in `localStorage` under `tripto_locale_v1`; an
authenticated preference is additionally persisted via `PATCH /api/v1/account/locale`
(`users.locale`) and restored after sign-in on any device.

## Architecture (DOM-swap + dynamic patterns)

The mobile app is a single large legacy renderer that emits English HTML. Rather than
rewrite it (which would risk booking/user-data flows), `public/i18n.js` translates the
rendered DOM after every render and for dynamically inserted sheets via a `MutationObserver`.
It translates text nodes and the `aria-label`, `title`, `placeholder` and `alt` attributes,
and sets `<html lang>`. This keeps English as the canonical in-source fallback while
non-English users never see English leaking through.

Three artifacts drive it, all precached by the service worker so the app is fully localized
offline:

- `public/lang/source-map.json` — 1,931 exact English phrase → stable key map. Static
  UI text (labels, buttons, headings, empty states, FAQ, marketing, errors) is matched by
  exact text-node/attribute equality.
- `public/lang/<locale>.json` — `{ locale, messages, plural }`. `messages` holds all
  2,146 keys (English + four translations); `plural` holds CLDR plural tables per noun.
- `public/lang/patterns.json` — dynamic (interpolated) strings that the exact map can't
  catch. `countNouns` routes `"{count} <noun>"` strings to the plural engine; `patterns`
  hold interpolation templates (e.g. delete confirmations with a user `{title}`). Each
  pattern has a `scope`: `all` (text nodes + attributes; used for numeric templates or
  long distinctive literals) or `attr` (attributes only, where `{title}`/`{name}` are user
  data — bounds the risk of a greedy match corrupting prose). Exact-match always runs first.

### Keys

Keys are meaningful and namespaced (`action.save`, `nav.account`, `error.account_is_unavailable`,
`booking.travel_essentials`), never opaque (`k30`, `button2`). Namespaces:
`action, a11y, account, booking, checklist, currency, dayplan, document, empty, error,
faq, form, map, marketing, nav, notification, sample, seo, toast, transport, ui, validation,
weather`.

## Translation quality

- Native, idiomatic, non-literal copy, produced against `docs/i18n-glossary.md` so every
  recurring concept uses one consistent term across all screens.
- Formality: German **Sie**, French **vous**, Spanish **tú**, Russian lowercase **вы**.
- Interpolation only — no string concatenation. `{placeholders}` are preserved exactly;
  a translation whose placeholder set differs from English falls back to English.
- Pluralization uses `Intl.PluralRules` per locale, including Russian `one/few/many/other`
  (e.g. `1 место`, `2 места`, `5 мест`, `21 день`).
- Dates/numbers/currency use `Intl.DateTimeFormat`/`NumberFormat` with the active locale.
  Timezone handling and stored data are untouched; ISO-only parsing stays `en-CA` where
  data correctness requires it.

## Not translated (by design)

User-generated content, traveler names, hotel/airline names, airport/currency codes,
flight numbers, booking/confirmation references, URLs, emails, file names, official
document content, API values and database IDs. Brand tokens (`Tripto`, `Tripto Plus`,
`Google`, `eSIM`, `PDF`, `FAQ`, `tripto.to`) are never translated.

## Validation

`npm run check:i18n` (alias `npm run i18n:check`) enforces: full coverage floor, English⇄
locale key parity (no missing/orphan keys), no empty values, placeholder-token parity vs
English, no Cyrillic leakage into de/fr/es, required plural categories per locale each
containing `{count}`, source-map integrity, patterns integrity (keys resolve, count-nouns
are real plural nouns, every pattern placeholder exists in each locale's message), and the
runtime wiring (i18n.js load order, patterns + service-worker precache, account locale route).

## Build pipeline

1. `scripts/i18n-assemble.mjs` — inventories UI strings, assigns namespaced keys, splits
   static vs dynamic, filters non-translatables.
2. `scripts/i18n-translate.workflow.mjs` — glossary-pinned translation (per language × batch).
3. `scripts/i18n-build-bundles.mjs` — writes the five locale bundles + source-map with
   English fallback and placeholder-integrity guard.
4. `scripts/i18n-build-patterns.mjs` — builds `patterns.json` (count-noun routing + scoped
   interpolation templates).

New UI should call `TriptoI18n.t(key, vars, fallback)` / `TriptoI18n.plural(nounKey, count)`
directly rather than relying on DOM-swap.

## Cache busting

The locale bundles and `patterns.json` are precached in `public/sw.js` under the versioned
shell cache (`tripto-shell-product-<token>`); `i18n.js` is served cache-first by its exact
`?v=` URL. Bump the shared shell token (see the deploy ritual) so a content change reaches
users.
